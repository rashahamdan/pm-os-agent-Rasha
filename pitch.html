Cortex

A PM chief-of-staff agent that turns one inbound task into a grounded, leadership-ready status update and a proposed backlog — checked by an independent critic, always stopped at a human checkpoint.

Rasha Hamdan

The problem

Status updates are repetitive but high-stakes

  • PMs lose hours each week assembling leadership status updates by hand.
  • The work is repetitive — but a wrong metric, a leaked roadmap, or a committed date has real blast radius.
  • A good fit for an agent — if it's bounded so it can draft without ever acting on its own.
The agent in one sentence

What Cortex does

Given a task like "write this week's leadership update," Cortex pulls the real project data (PRs, issues, past updates, roadmap, norms), drafts a grounded status update with an honest red/yellow/green call, and proposes a capped set of next-sprint stories — then stops for human review.

By design it can draft and propose, never act.

M2 · Loop spec

Trigger, done, and stop conditions

  • Trigger: heartbeat (every 3h, 9am–6pm UK, weekdays) → checks for inbound tasks
  • Definition of done: grounded update + proposed stories that pass the critic and reach the human checkpoint
  • Stop: critic pass → queue · revisions/iterations exhausted → escalate
  • Context: retrieve narrow slices; task brief in long-context
M3 · Orchestration

Single agent + one independent validator

heartbeat → CORTEX (draft + propose) → CRITIC (fresh context) → pass → HITL checkpoint
                                          └ fail → revise (≤2) → escalate
  • Critic runs on isolated context — can't inherit the drafter's blind spots.
  • No research/reader fleet — parallelism & context pressure don't apply at this scale.
  • The one split worth its coordination cost: independent validation.
M4 · Memory & context

Retrieve the volatile, keep the bounded

  • Retrieve activity, past updates, roadmap, norms — the narrow, current, shareable slice, fresh each run.
  • Long-context only the bounded task brief.
  • Near-stateless across runs: working memory is purged; facts are retrieved fresh — little to drift or poison.

The critic rejects a bad draft; the jailbreak is refused

Injection ignored — nothing posted, no roadmap leak, no date committed.

M5 · Evals

Grade the path, not just the answer

  • 6 trajectory cases (eval-cases.json): happy, missing-data, jailbreak, grounding-failure recovery, bound-trip, JIT-denial.
  • evals.py runs them and asserts terminal outcome + safety invariants (nothing posted/leaked).
  • Latest run: 5 pass, 1 manual. Run the replay set on every change; block a regressing merge.
M6 · What I learned

The best design moves were subtractions

  • Friction: the validator was harder than the agent — a cheap critic gave inconsistent verdicts; only a stronger critic model made them repeatable.
  • Learning: safety lives in infrastructure, not the prompt — a capability the agent doesn't have can't be misused.
  • Aha: no publish tool, less critic context, near-stateless memory — each subtraction killed a class of failure. A bounded agent is a more trustworthy agent.
M6 · Trust Ladder & autonomy

Supervised today — widened on evidence

  • Current rung: supervised — every run ends at a human checkpoint; nothing posted by construction.
  • Per-segment dial: cautious PM stays supervised · high-trust lead could reach bounded-autonomous · exec never does.
  • Widen rule (pre-committed): replay set 100% for 4 weeks + <1% edit rate + <1% critic false-positives + zero incidents → dial up one segment. Any incident drops it back.
